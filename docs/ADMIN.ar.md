# لوحة MH — دليل التشغيل والمراجعة

تم التنفيذ على `feature/arabic-admin`. لم يُدمج الفرع ولم يُنشر الموقع. نُشرت خدمة OAuth المستقلة، وضُبطت بيانات تطبيق GitHub داخلها. الصفحة الأصلية وجميع الملفات الأصلية محفوظة. نجح فحص جاهزية OAuth والتحويل إلى GitHub؛ ما زال تسجيل الدخول الكامل وحفظ مسودة فعلية بحاجة إلى اختبار بحساب المدير.

## المعمارية

- GitHub Pages يستضيف الموقع وملف `content/site.json` ولوحة `/admin/` فقط. لا توجد قاعدة بيانات أو كلمات مرور في JavaScript.
- Decap CMS 3.17.3 مثبت محليًا في `admin/vendor` لتجنب الاعتماد على CDN عند فتح المحرر. واجهة المحتوى مترجمة إلى العربية مع اتجاه RTL. بعض رسائل الطرف الثالث الفنية تظل بالإنجليزية.
- GitHub هو مخزن المحتوى وسجل المراجعات. الصور والفيديوهات الأصلية تبقى في `assets`. التعديلات على المحتوى في JSON، والرفع عبر مكتبة الوسائط إلى `assets`. يمكن استخدام روابط HTTPS لوسائط مستضافة خارجيًا.
- `oauth/worker.js` خدمة Cloudflare Worker مستقلة لتسجيل دخول GitHub. تحفظ `CLIENT_SECRET` على الخادم فقط، وتتحقق من حالة OAuth وقائمة المديرين وصلاحية الكتابة على المستودع. تعيد رمز الوصول إلى محرر Decap عبر postMessage محصور في أصل الموقع المحدد. Decap يحتفظ بجلسة الدخول في المتصفح؛ استخدم جهازًا موثوقًا وسجّل الخروج بعد العمل وفعّل المصادقة الثنائية في GitHub.
- نطاق GitHub OAuth المستخدم `public_repo` يمنح صلاحيات على المستودعات العامة التي يملكها الحساب، وليس هذا المستودع وحده. استخدم حساب إدارة محدود الصلاحيات. للمستودعات الخاصة يلزم تصميم ومراجعة النطاقات من جديد؛ لا توسعها تلقائيًا.

## إعداد الدخول الحقيقي — بعد المراجعة فقط

1. في GitHub Settings → Developer settings → OAuth Apps أنشئ تطبيقًا. Homepage URL هو رابط الموقع، وAuthorization callback URL هو `https://<worker-host>/callback`. لا تضع Client Secret في المستودع أو المحادثة.
2. أنشئ Worker من `oauth/worker.js` باستخدام Cloudflare Dashboard أو Wrangler. ملف `oauth/wrangler.toml` يحدد ملف الدخول. هذه خدمة خارج GitHub Pages وقد تحتاج حساب Cloudflare وفق حدود خطتك. أُنشئت ونُشرت، وضُبطت فيها بيانات تطبيق GitHub OAuth.
3. عرّف `CLIENT_ID` و`CMS_ORIGIN` (أصل HTTPS فقط، مثل `https://username.github.io`، دون مسار المشروع) و`ALLOWED_USERS` (أسماء حسابات GitHub مفصولة بفواصل) و`REPOSITORY=bbbfhjhfhfhfb-creator/mh-mohammed-hanish` في إعدادات Worker. ضع `CLIENT_SECRET` في Cloudflare Secrets، أو `wrangler secret put CLIENT_SECRET`. لا توجد قيم سرية تجريبية صالحة داخل الملفات.
4. استبدل `backend.base_url` في `admin/config.yml` بعنوان Worker الفعلي. القيمة الحالية `https://mh-admin-oauth.hmwdyalrayd0.workers.dev` تشير إلى الخدمة المنشأة لهذا المشروع. `auth_endpoint` هو `auth`.
5. امنع تعديلات الإنتاج المباشرة: احمِ فرع الإنتاج في GitHub بقواعد تتطلب Pull Request ومراجعة، دون تجاوز لحساب الإدارة. تحقق من إعدادات Pages الحالية قبل أي دمج. أبقِ `backend.branch=feature/arabic-admin` أثناء المراجعة؛ «النشر» داخل Decap يدمج مسودته إلى هذا الفرع فقط. لا تغيّره إلى فرع الإنتاج إلا بقرار منفصل بعد المراجعة وإعداد الحماية.
6. اختبر بحساب مدير مسموح، وحساب غير مسموح، وإلغاء الدخول، وانتهاء الجلسة. احفظ مسودة وتأكد أن PR يستهدف فرع المراجعة وأن موقع الإنتاج لم يتغير. اختبارات OAuth الآلية تستخدم محاكاة GitHub، وليست إثباتًا لتكامل حساب حقيقي.

لا تحتاج مكتبة الوسائط الحالية إلى خدمة تخزين إضافية. يُفضّل ضغط الفيديوهات الكبيرة أو تخزين النسخ الجديدة في خدمة مثل Cloudinary أو R2 بروابط HTTPS عامة (التكلفة وسياسة الحذف وCORS تضبط هناك). لا يُدمج تكامل رفع خارجي تلقائيًا دون إعداداته. حد اختيار الملفات المضبوط في الحقول 25MB؛ GitHub وواجهة API لهما حدود مستقلة، وقد تفشل ملفات كبيرة. لا يُحوّل شيء إلى Git LFS: GitHub Pages لا يخدم محتويات LFS مباشرة. لا تُنقل الملفات القديمة أو تُحذف لتجاوز الحدود.

## الاستخدام

افتح `/admin/` ثم «فتح المحرر الآمن» وسجّل الدخول بحساب GitHub المصرح. حرّر «المحتوى والإعدادات»:

- الصور والفيديوهات: أضف عنصرًا، اختر النوع والملف والغلاف والنص البديل، وحدد معرّف تصنيف موجود. اسحب العناصر للترتيب، وأوقف «ظاهر في الموقع» لإخفاء عمل دون حذف ملفه. يمكن حذف عنصر المعرض من القائمة، مع إبقاء الأصل في الوسائط. أسماء التصنيفات عربية ومعرّفاتها أحرف إنجليزية صغيرة وشرطات.
- الواجهة: اختر الخلفية وصورة غلاف الفيديو ورتّب فيديوهاتها؛ قائمة فارغة تُظهر الخلفية الثابتة. صورة غلاف الفيديو تُستخدم كـ poster وقد لا تظهر أثناء التشغيل.
- من أنا: عدّل الصورة والعناوين والفقرات في مواقعها الأصلية، ومجالات العمل والرؤية. عدد العناوين والفقرات ثابت لحفظ بنية القسم. الخدمات وروابط التواصل قوائم قابلة للإضافة والحذف والترتيب.
- راجع المعاينة المباشرة قبل الحفظ. المعاينة تستخدم نفس التصميم ومحرّك عرض الموقع وتدعم الوسائط الجديدة عبر getAsset. على الهاتف استخدم الزر السفلي «معاينة المسودة» ثم «العودة للتحرير» للتبديل بين العرضين.
- احفظ كمسودة ثم غيّر الحالة إلى «قيد المراجعة». النشر في CMS ليس بديلًا عن موافقة الدمج النهائية أو حماية GitHub. لا تضغط النشر قبل المراجعة.

فحص الملفات في صفحة اللوحة يفحص آخر ملف JSON المخدوم، وليس تعديلات المسودة غير المحفوظة. طلبات HEAD لا تنزّل الفيديوهات. 404 يعني مفقود؛ فشل الشبكة أو CORS يعني «غير مؤكد» وليس مفقودًا. المرجع `assets/event-video-03.mp4` محفوظ في HTML وJSON ويظهر كمفقود. راجعه قبل استبداله أو حذفه. حذف ملف من مكتبة Decap قد يكسر مراجع HTML القديمة؛ الحذف يتطلب مراجعة جميع المراجع في الفرع وPR. لا توجد آلية حذف تلقائي أو تنظيف ملفات.

## التشغيل والاختبارات

من جذر المشروع شغّل `python3 -m http.server 8000 --bind 127.0.0.1`. لا يلزم بناء الموقع. يحتاج فحص المتصفح Node وPlaywright وChromium. ثبّت أدوات الاختبار فقط باستخدام `npm ci` ثم عند غياب متصفح النظام `npx playwright install chromium` وحدد `CHROMIUM_PATH` لمساره.

- `npm test`: اختبارات OAuth وموانع المدخلات الخطرة.
- `npm run test:browser`: بعد تشغيل الخادم، يختبر الموقع والمحرر ومعاينة مسودة غير محفوظة وحفظها في مستودع داخل ذاكرة المتصفح فقط. يعترض إعدادات backend في الاختبار وحده؛ لا يوجد زر دخول تجريبي أو backend تجريبي في إعدادات الموقع.
- `git diff --name-status`: يجب ألا يظهر حذف ملفات أصلية. يمكن مقارنة الأصول باستخدام `git diff --exit-code <base> -- assets style.css`.

للرجوع عن محتوى منشور، استخدم PR يعكس commit المحتوى بعد المراجعة. لا تمسح تاريخ Git أو ملفات الأصول. يجب إعادة اختبار التشغيل الفعلي للفيديو على الأجهزة المستهدفة، وتكامل OAuth وPR بعد إعداد الخدمة الخارجية. لوحة الملفات لا تتحقق من ترميز الفيديو أو انتهاء صلاحية روابط خارجية.

## المدخل المخفي في الشعار

انقر شعار أعلى الموقع خمس مرات متتابعة (بفاصل أقل من 1.8 ثانية بين النقرات)، ثم أدخل `1233` أو `١٢٣٣` واضغط «متابعة». الرمز يفتح مسار `/admin/` فقط، ولا يمنح صلاحية التعديل أو يتجاوز GitHub OAuth. الرمز ظاهر في الشيفرة العامة بحكم طبيعة GitHub Pages، وليس كلمة مرور. يبقى الوصول المباشر لمسار الإدارة ممكنًا، وتبقى الكتابة محمية بمصادقة GitHub وصلاحيات المستودع. يدعم المدخل الهاتف ولوحة المفاتيح؛ اضغط Enter على رابط الشعار خمس مرات. Escape أو «إلغاء» يغلقان النافذة دون تغيير الموقع.

لحالة التحقق وخطوات GitHub OAuth وعنوان callback الفعلي، راجع [حالة الخدمة](../oauth/SETUP.ar.md).
